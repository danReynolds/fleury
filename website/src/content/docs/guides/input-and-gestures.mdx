Click a field, drag a handle, or scroll a pane. Fleury routes pointer input to
the widgets displayed at that cell. Start with the control that owns the
interaction so pointer, keyboard, and semantic actions stay together:

| What you are building | Start with |
| --- | --- |
| An action or editable field | `Button`, `TextInput`, or `TextArea` |
| A custom press or draggable handle | `GestureDetector`, with keyboard focus and actions |
| Hover feedback, a cursor hint, or custom wheel handling | `MouseRegion` |
| A region of text to select and copy | `SelectionArea` |

In a terminal, enable mouse reporting when starting your app. `mouseMotion`
includes clicks, drags, scrolling, and hover:

```dart
runApp(const MyApp(), mode: const TerminalMode(mouseMotion: true));
```

Mouse reporting is off by default to preserve the terminal’s native text
selection. Use `mouse: true` when you only need clicks, drags, and scrolling.
The browser demos already receive pointer input.

Positions and movement are measured in **terminal cells**. A pointer region
uses its child's laid-out size and respects clipping. Padding inside a detector
enlarges its target; padding outside moves that target. `localPosition` starts
at the receiving region's origin, while `globalPosition` starts at the app
surface.

`Button` keeps Enter/Space activation, focus, semantics, and non-selectable
content. `onSecondaryPressed` handles a completed right click without calling
`onPressed`. Setting `onPressed: null` disables both actions.

`CellStyle.interactive(pressed: …)` applies during a primary pointer press and
clears on release, cancellation, or disabling. It layers after focus paint and
before validation paint. Keyboard and semantic activation are immediate actions;
they do not hold a pressed visual while waiting for a key release that a native
terminal may not report. See [theming](/fleury/guides/theming/) for the style cascade.

## Build a custom press target

Use the lower-level callbacks when you need to react to a gesture's lifecycle.
This tile reports **Pressed…**, **Opened notes.md**, or **Cancelled**. Press and
release in the same cell to open it; moving to another cell cancels the tap,
even inside the tile. A release outside or loss of surface input also cancels.
Right-click or **I** shows details; Enter/Space opens; Tab moves to **Details**.

`onTapDown` starts the visual. A completed primary click calls `onTapUp`, then
`onTap`; a cancelled press calls `onTapCancel` instead. Right clicks use
`onSecondaryTap` and do not start the primary pressed visual.

The custom target supplies the behavior that `Button` normally owns:
`Focus` and `KeyBindings` for keyboard access, `FocusDetector` for a visible
focus cue, `Semantics` for its action, and `SelectionArea.disabled` so dragging
its label does not select text. Its `FocusNode` is owned and disposed by the
state, as shown in the complete source.

The innermost tap/drag target owns the press. Wrapping a `Button` in another
`GestureDetector` does not observe its presses or add a right-click handler;
use the button's own style and action properties. Hover and wheel input have
different ancestor behavior, demonstrated below. For an overlay that must block
input to covered widgets, use `AbsorbPointer`; its child controls remain usable.

## Drag a handle

Grab the vertical divider and move it left or right. Keep dragging beyond the
handle, then release: it retains the gesture until you finish. You can also
focus it and use **← / →**. Held arrows keep resizing. Tab moves to **Reset
width**, and Shift+Tab returns to the handle; its highlight follows focus.

`details.delta.col` is movement since the previous report. It stays stable
when resizing moves the handle itself. The first movement calls both
`onDragStart` and `onDragUpdate` with the same delta: use start for visual state
and apply movement in update, as above. Once captured, local positions can fall
outside the handle's bounds. `globalPressPosition` retains the original press.

`MouseRegion(cursor: MouseCursor.resizeLeftRight)` gives the handle its resize
cursor in a browser and in terminals that negotiate pointer-shape support.
The cursor stays with the captured drag. `onDragEnd` handles release;
`onDragCancel` handles interruption, such as the app surface losing focus or
the handle being clipped out of view. Cancellation ends feedback; this example
keeps the width already reached. The separator text opts out of selection with
`allowSelect: false`, and its semantics expose the current width and resize actions.

## Select text to copy

Type in **Reply**, then drag from the note’s heading into the next line.

it. The count below the note is outside the selection area.

`FleuryApp` already enables drag selection for ordinary text. Use `SelectionArea`
for a region with its own selection, callbacks, or options such as
`copyOnRelease: true`. Selecting the note gives its region keyboard focus;
Copy, Select All, and Escape now act on the note. Clicking Reply returns focus
to the field. You do not need an extra `Focus` wrapper.

In a native terminal, a modifier used to bypass application mouse reporting
may select terminal text instead of delivering a Shift-click to Fleury.
The browser walkthrough demonstrates Fleury's own selection path; native
selection and clipboard behavior depend on the terminal and host.

Move from **notes.md** onto **Pin**: the row stays hovered while the button
receives its own interaction. Scroll **Recent** to its end, then keep
scrolling: **All notes** moves to reveal older notes. Turn on **Keep scrolling
in Recent** and repeat to see the wheel stop at that pane’s edge.

`ScrollView` and `ListView` handle the wheel. At an edge, their default
`edgeBehavior: EdgeBehavior.bubble` offers the event to a scrollable ancestor.
The checkbox switches the inner pane to `EdgeBehavior.contain`.

Hover follows the hit target's ancestors, so the row stays hovered over its
button. For a custom wheel handler, `MouseRegion.onScroll` receives a cell
delta; return `true` to consume it or `false` to offer it to an ancestor.
Wheel events do not fall through to an obscured sibling. Shift+vertical wheel
is delivered as horizontal movement.
