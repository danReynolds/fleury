Start with the control that owns the interaction. `Button` handles activation,
text fields handle editing, and scroll views handle scrolling. Add a gesture
when your interface needs behavior those controls don't provide.

The app owns `open`; the button owns how input reaches `onPressed`.
Hold the mouse button to see its `pressed:` style. Keyboard activation is
immediate; held keyboard styling isn't currently supplied.

A different appearance still uses `Button`: provide a composed `child` and
`appearance: ButtonAppearance.plain` for a file tile without brackets.
`onSecondaryPressed` adds a right-click action; give that action a keyboard
route too. `onPressed: null` disables the control.

The same principle applies to `TextInput` and `TextArea`: caret placement,
drag selection, and keyboard editing are built in. See
[forms & validation](/fleury/guides/forms/) for collecting and using their values.

## Add a gesture when movement matters

A resize handle needs movement, not just activation. `GestureDetector`
captures its drag and keeps receiving updates beyond the handle's bounds.
Drag the divider, then resize with **← / →**: both paths call `resize`.

Movement is measured in terminal cells. Apply `details.delta.col` in
`onDragUpdate`; ending or cancelling the drag clears feedback and keeps the
width reached. **Tab** moves to Reset width.

A custom gesture supplies pointer behavior. Attach the arrow bindings with
`KeyBindings` around the handle's `Focus`. The full example also uses `Semantics`
to expose the width and resize actions. Every input path calls the same operation.

`onTapDown` starts the held feedback. A completed tap calls `onTapUp`, then
`onTap`; cancellation calls `onTapCancel`. Moving to another terminal cell
cancels the tap, even inside the tile. Keep that feedback separate from
application state. The full example adds focus, Enter/Space, and semantic
activation; `SelectionArea.disabled` keeps the tile's label out of selection.

</details>

<details>
<summary>Coordinates and capture</summary>

`localPosition` is relative to the target; `globalPosition` is relative to the
app. A captured drag can have local coordinates outside the target.
The first movement calls both `onDragStart` and `onDragUpdate` with the same
delta, so apply movement only in update. Padding inside a detector enlarges
its target. Clipping limits it and cancels a gesture if the target disappears.

</details>

## Compose input without taking it over

Hover belongs to a region; a press belongs to its target. Move across the file
row and onto **Pin**. The row stays highlighted while the button handles the
click. `MouseRegion` observes its children without replacing their controls.

An outer `GestureDetector` doesn't observe an inner button's taps: the
innermost tap/drag target owns the press. Use the button's callback for its
action and `MouseRegion` for surrounding hover feedback.

Wheel input has a different rule: a scroll view can pass it to an ancestor
at its edge. [Nested scrolling](/fleury/guides/lists-and-scrolling/#nested-wheel-input)
shows when to let it continue and when to contain it.

## Enable pointer input in a terminal

The browser demos receive pointer input automatically. In a terminal, enable
clicks, drags, scrolling, and hover when starting the app:

```dart
runApp(const MyApp(), mode: const TerminalMode(mouseMotion: true));
```

Mouse reporting is opt-in because it takes over terminal text selection.
Use `mouse: true` when hover isn't needed. A terminal-specific modifier may
bypass the app for native selection.
