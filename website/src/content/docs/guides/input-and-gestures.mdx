`onTapDown` starts feedback; `onTapUp` or `onTapCancel` clears it. Enter and
Space share one `KeyBinding` through `aliases`. Use `Button` for ordinary
actions—it already supplies focus, keyboard access, and semantics.

<details>
<summary>How nested targets behave</summary>

The innermost tap/drag target owns the press. A `GestureDetector` around a
`Button` cannot observe its taps; use the button's style and callbacks.
`AbsorbPointer` blocks covered widgets while leaving its own child controls
usable. Hover and scrolling follow ancestors, as the final demo shows.

</details>

`details.delta.col` measures movement in cells. Apply it in `onDragUpdate`;
use start, end, and cancel for feedback. Cancellation keeps the width already
reached in this example.

<details>
<summary>Coordinates and capture</summary>

`localPosition` is relative to the target; `globalPosition` is relative to the
app. A captured drag can have local coordinates outside the target.
The first movement calls both `onDragStart` and `onDragUpdate` with the same
delta, so apply movement only in update. Padding inside a detector enlarges
its target. Clipping limits it and cancels a gesture if the target disappears.

</details>

## Use the mouse in a terminal

These browser demos receive mouse input automatically. For a native app,
enable clicks, drags, scrolling, and hover at startup:

```dart
runApp(const MyApp(), mode: const TerminalMode(mouseMotion: true));
```

Mouse reporting is currently opt-in because it takes over terminal text
selection. `mouse: true` enables clicks, drags, and scrolling without hover.
A terminal-specific modifier may bypass the app for native selection.

Continue with [key bindings](/fleury/guides/focus-and-keyboard/),
[focus](/fleury/guides/focus/), or [interactive styles](/fleury/guides/theming/).
Run all six examples' tests with
`cd website/examples && dart test test/input_guide_test.dart`.
