Opening a file should work the same way from a click or the keyboard. Fleury's
controls connect those inputs to one application action and handle focus and
activation for you. Gestures let you build interactions that depend on
movement, such as resizing a pane. The examples below show when to use each
and how to combine them in nested widgets.

## Use a control for an action

A button represents an action, such as opening a note. Give it a callback that
performs the action, and Fleury connects mouse clicks, keyboard activation, and
assistive tools to that callback. Each way of activating the button therefore
changes application state in the same way.

Focus determines which control receives keyboard input. Clicking this button
focuses it; **Enter** and **Space** then invoke its action. The underline makes
that focus visible. The callback only changes whether the note is open; it
doesn't need to distinguish a click from a key press.

Choose a control for the interaction it provides. A clickable file tile can
still be a button with custom content and a plain appearance. Likewise, text
fields provide caret movement, selection, and editing. Reusing those behaviors
leaves your code responsible for the action or value your application needs.

<details>
<summary>Button appearance and secondary actions</summary>

The pressed style gives feedback while the mouse button is held. Keyboard
activation is immediate and doesn't currently show a held state. Customizing
this appearance preserves the button's focus and activation behavior.

The [button reference](/fleury/widgets/button/) covers custom content, plain
appearance, and right-click actions. Provide a keyboard route for any secondary
action as well. For text entry, continue with the [forms guide](/fleury/guides/forms/).

</details>

## Turn dragging into a resize

Resizing a pane requires a stream of movement while the pointer is held down.
`GestureDetector` recognizes the drag and reports its progress. Your application
decides what that movement means: here, horizontal movement changes the width
of the file pane.

Once a drag starts, the handle **captures** it: movement and release keep
reaching that handle after the pointer leaves its bounds. This lets a narrow
divider keep working as you move away from it. Each update reports a delta—the
movement since the previous report—in terminal cells. Adding that delta to the
width makes the pane follow the pointer.

The arrow keys call the same resize function, so dragging and keyboard input
share the width limits. A gesture detector supplies only the pointer behavior.
The full example also makes the handle focusable and exposes its value and
resize actions to assistive tools. These are responsibilities the button
provided for us in the first example.

<details>
<summary>Keep press feedback separate from app state</summary>

Pressing a control starts an interaction; it doesn't yet mean the action should
happen. A custom target may need to show that a press is in progress and clear
that feedback if the user cancels. Keep this temporary feedback separate from
lasting state, such as which file is open.

Only a completed tap invokes the action. In Fleury, moving to another cell
cancels the tap even if the pointer remains inside the target. The cancellation
handler clears the held feedback; it leaves the open note alone. Use a standard
button when you only need its pressed appearance.

</details>

<details>
<summary>Coordinates and target bounds</summary>

Use `localPosition` to locate a pointer within a target and `globalPosition` to
locate it within the app. During a captured drag, the pointer can be outside the
target, so local coordinates can fall outside its bounds.

For resizing, use the movement delta. The handle itself moves as the pane
changes width, while the delta still describes the pointer's movement. The
first movement reports both drag start and update; apply its delta only in the
update callback to avoid resizing twice.

A detector's target is the area laid out for its child. Put padding inside the
detector to give a small handle a larger hit area. Clipping limits that area;
if the target disappears, the gesture is cancelled.

</details>

## Add hover to a group of controls

Some visual feedback belongs to a whole item, even when that item contains
several controls. A file row, for example, should stay highlighted as the
pointer moves from its name to a button inside it. `MouseRegion` treats the row
and its children as one area and reports when the pointer enters or leaves it.

A pointer over a child is also inside its parent's bounds. That's why moving
onto **Pin** keeps the row hovered: the pointer hasn't left the enclosing area.
The border makes that area visible, including the space between the filename
and button.

A tap follows a different rule. The button receives presses directed at it; an
enclosing gesture detector won't receive a second copy. Put the action on the
button and shared hover feedback on the containing row.

Scrolling has its own handoff: when an inner pane reaches its edge, an outer
pane can continue scrolling. See [nested scrolling](/fleury/guides/lists-and-scrolling/#nested-wheel-input)
for choosing whether wheel input stays in a pane or reaches its parent.

<details>
<summary>Keep copied text separate from controls</summary>

Ordinary app text is selectable by default. If a note should be copied without
the status messages around it, wrap just the note in a `SelectionArea`. That
boundary also gives it its own selection callback and options. For text used as
a handle, set `allowSelect: false` so dragging manipulates the control without
selecting its label.

</details>

## Enable pointer input in a terminal

Terminals normally keep mouse input for their own text selection. An interactive
app must ask the terminal to send that input to it instead. Enable mouse
reporting when starting the app:

```dart
runApp(const MyApp(), mode: const TerminalMode(mouseMotion: true));
```

This enables clicks, drags, scrolling, and hover. Use `mouse: true` when hover
isn't needed. The browser demos already receive pointer input. In a terminal,
a terminal-specific modifier may bypass the app for native text selection.
