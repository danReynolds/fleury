Fleury supports state at three levels: **local state** within a widget,
**tree state** shared by descendants, and **global state** used across
widgets, services, and controllers.

| Level | Use it for | Main API |
|---|---|---|
| Local state | Data used by one widget | `State` and `setState` |
| Tree state | Data shared by descendants | `Scope` and `ScopeBuilder` |
| Global state | Data shared by widgets, services, and controllers | `Notifier` and `NotifierBuilder` |

## Local state

Use a `StatefulWidget` when a value belongs to one part of the UI. Keep it in
`State` and update it with `setState`:

<CodeDemoSplit codeMaxHeight="32rem">
<Fragment slot="code">
```dart
class _LocalCounterState extends State<LocalCounter> {
  int count = 0;

  @override
  Widget build(BuildContext context) => Column(
    children: [
      Text('Count: $count'),
      Button(
        text: 'Increment',
        onPressed: () => setState(() => count++),
      ),
    ],
  );
}

class LocalCounter extends StatefulWidget {
  const LocalCounter({super.key});

  @override
  State<LocalCounter> createState() => _LocalCounterState();
}
```
</Fragment>
<FleuryExample slot="demo" id="state.local-counter" cols={34} rows={9} interactive />
</CodeDemoSplit>

Press **Increment** to change `count`. `setState` schedules a rebuild so the
widget displays the new value.

When nearby widgets share state, keep it in their parent and pass values and
actions through constructors. A scope helps when more of the tree needs access.

## Tree state

`Scope` shares a value with descendants without passing it through each
widget's constructor. Here, the screen owns a plain `Project` value, and a
separate `ProjectName` widget reads it with `ScopeBuilder<Project>`.

The button replaces the project inside `setState`. That rebuilds the scope
with the new value and updates the reader:

<CodeDemoSplit file="project_scope.dart" codeMaxHeight="32rem">
<Fragment slot="code">
```dart
class _ProjectScopeScreenState
    extends State<ProjectScopeScreen> {
  var project = const Project('Atlas');

  @override
  Widget build(BuildContext context) => Column(
    crossAxisAlignment: CrossAxisAlignment.start,
    children: [
      Scope(
        project,
        child: const ProjectName(),
      ),
      Button(
        text: 'Switch project',
        onPressed: switchProject,
      ),
    ],
  );

  void switchProject() => setState(() {
    project = project.name == 'Atlas'
        ? const Project('Beacon')
        : const Project('Atlas');
  });
}

class ProjectName extends StatelessWidget {
  const ProjectName({super.key});

  @override
  Widget build(BuildContext context) =>
      ScopeBuilder<Project>(
        builder: (context, project) =>
            Text('Project: ${project.name}'),
      );
}

class ProjectScopeScreen extends StatefulWidget {
  const ProjectScopeScreen({super.key});

  @override
  State<ProjectScopeScreen> createState() =>
      _ProjectScopeScreenState();
}

class Project {
  const Project(this.name);
  final String name;
}
```
</Fragment>
<FleuryExample slot="demo" id="state.project-scope" cols={38} rows={9} interactive />
</CodeDemoSplit>

Press **Switch project** to alternate between Atlas and Beacon.
`ProjectName` can sit anywhere below the scope: it finds the closest parent
`Scope<Project>`.

### Reading from BuildContext

`context.scope<Project>()` reads the value directly inside a widget's `build`
method. The same update flow works here: the screen owns the project, the
button changes it, and `ProjectLabel` rebuilds with the new value:

<CodeDemoSplit files={['project_screen.dart', 'project_label.dart']} initialFile="project_screen.dart" codeMaxHeight="32rem">
<Fragment slot="code-0">
```dart
class _ProjectScreenState
    extends State<ProjectScreen> {
  var project = const Project('Atlas');

  @override
  Widget build(BuildContext context) => Column(
    crossAxisAlignment: CrossAxisAlignment.start,
    children: [
      Scope(
        project,
        child: const ProjectLabel(),
      ),
      Button(
        text: 'Switch project',
        onPressed: switchProject,
      ),
    ],
  );

  void switchProject() => setState(() {
    project = project.name == 'Atlas'
        ? const Project('Beacon')
        : const Project('Atlas');
  });
}

class ProjectScreen extends StatefulWidget {
  const ProjectScreen({super.key});

  @override
  State<ProjectScreen> createState() =>
      _ProjectScreenState();
}

class Project {
  const Project(this.name);
  final String name;
}
```
</Fragment>
<Fragment slot="code-1">
```dart
class ProjectLabel extends StatelessWidget {
  const ProjectLabel({super.key});

  @override
  Widget build(BuildContext context) {
    final project = context.scope<Project>();
    return Text('Project: ${project.name}');
  }
}
```
</Fragment>
<FleuryExample slot="demo" id="state.project-context" cols={38} rows={9} interactive />
</CodeDemoSplit>

`ScopeBuilder` rebuilds its builder; `context.scope` rebuilds the widget that
reads the value. Otherwise they are the same read: both find the closest parent
scope, follow its updates, and stay subscribed until the widget leaves the
tree. Read a scope in `build`, `initState`, or `didChangeDependencies`; an event
handler uses the value read there. When a scope is optional, add `?` to the
type: `context.scope<Project?>()` returns null when no `Scope<Project>` is
above.

## Global state

A shopping cart can be used by several screens and a checkout service. Keep
that state in a model outside the widget tree so they can all work with the
same instance.

A `Notifier` lets that model announce changes. Update its fields, then call
`notify()`. Widgets observe it with `NotifierBuilder`:

<CodeDemoSplit files={['cart.dart', 'cart_view.dart']} initialFile="cart.dart" codeMaxHeight="32rem">
<Fragment slot="code-0">
```dart
class Cart extends Notifier {
  int _itemCount = 0;
  int get itemCount => _itemCount;

  void addItem() {
    _itemCount++;
    notify();
  }
}

final cart = Cart();
```
</Fragment>
<Fragment slot="code-1">
```dart
class CartView extends StatelessWidget {
  const CartView({super.key, required this.cart});
  final Cart cart;

  @override
  Widget build(BuildContext context) {
    return NotifierBuilder(
      notifier: cart,
      builder: (context, cart) => Column(
        children: [
          Text('Items: ${cart.itemCount}'),
          Button(
            text: 'Add item',
            onPressed: cart.addItem,
          ),
        ],
      ),
    );
  }
}
```
</Fragment>
<FleuryExample slot="demo" id="state.cart-notifier" cols={38} rows={9} interactive />
</CodeDemoSplit>

Press **Add item**. The model changes its count, calls `notify()`, and
`NotifierBuilder` rebuilds the display. Create one cart and pass it to the
widgets and services that need it. A service can call `cart.addItem()` on that
same instance without a widget or build context.

### Listening from BuildContext

A widget can also observe the cart with `context.listen(cart)`. It returns the
model and rebuilds this widget when the model notifies:

<CodeDemoSplit file="cart_context_view.dart" codeMaxHeight="32rem">
<Fragment slot="code">
```dart
class CartContextView extends StatelessWidget {
  const CartContextView({super.key, required this.cart});
  final Cart cart;

  @override
  Widget build(BuildContext context) {
    final model = context.listen(cart);
    return Column(
      children: [
        Text('Items: ${model.itemCount}'),
        Button(
          text: 'Add item',
          onPressed: model.addItem,
        ),
      ],
    );
  }
}
```
</Fragment>
<FleuryExample slot="demo" id="state.cart-context" cols={38} rows={9} interactive />
</CodeDemoSplit>

`NotifierBuilder` rebuilds its builder; `context.listen` rebuilds the widget
that calls it. Both manage their subscriptions automatically.

### Value notifiers

`ValueNotifier<T>` extends `Notifier` with a single `.value` property.
Assigning a different value sends the notification for you.

Here's the cart count without a custom model, using `context.listen` to read it:

<CodeDemoSplit file="cart_count.dart" codeMaxHeight="32rem">
<Fragment slot="code">
```dart
final count = ValueNotifier<int>(0);

class CartValueView extends StatelessWidget {
  const CartValueView({super.key, required this.count});
  final ValueNotifier<int> count;

  @override
  Widget build(BuildContext context) {
    final items = context.listen(count).value;
    return Column(
      children: [
        Text('Items: $items'),
        Button(
          text: 'Add item',
          onPressed: () => count.value++,
        ),
      ],
    );
  }
}
```
</Fragment>
<FleuryExample slot="demo" id="state.cart-value" cols={38} rows={9} interactive />
</CodeDemoSplit>

**Add item** now updates `count.value` directly. The same value notifier can
also be read with `NotifierBuilder`.

Use `Notifier` when a model needs its own fields and actions; use
`ValueNotifier` when one changing value is enough.
