Fleury is a reactive widget framework: the UI reflects the current state and
updates when that state changes. State can stay local to a widget, live
independently in a notifier, or be shared with a subtree through `BuildContext`.

| State scope | Use |
|---|---|
| Local state owned by a widget | `StatefulWidget` and `setState` |
| Shared state with an independent owner | [Notifiers](#notifiers) |
| Contextual state scoped to a widget subtree | [Scope](#sharing-state-through-the-tree) |

## Local state

Use a `StatefulWidget` when a value belongs to one part of the UI. Update it
with `setState`:

<CodeDemoSplit layout="demo-wide">
<Fragment slot="code">
```dart
class Counter extends StatefulWidget {
  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int count = 0;

  @override
  Widget build(BuildContext context) => Column(
    children: [
      Text('Count: $count'),
      Button(
        label: 'Increment',
        onPressed: () => setState(() => count++),
      ),
    ],
  );
}
```
</Fragment>

### Sharing local state

Nearby widgets can share state without another mechanism. Move the value to
their closest common parent, then pass the value and callbacks to the children
that use them:

<CodeDemoSplit
  files={['shared_counter.dart', 'counter_widgets.dart']}
  initialFile="shared_counter.dart"
  layout="demo-wide"
>
<Fragment slot="code-0">
```dart
class _SharedCounterState extends State<SharedCounter> {
  int count = 0;

  @override
  Widget build(BuildContext context) => Column(
    children: [
      CounterValue(value: count),
      CounterButton(
        onPressed: () => setState(() => count++),
      ),
    ],
  );
}
```
</Fragment>
<Fragment slot="code-1">
```dart
class CounterValue extends StatelessWidget {
  const CounterValue({required this.value});
  final int value;

  @override
  Widget build(BuildContext context) => Text('Count: $value');
}

class CounterButton extends StatelessWidget {
  const CounterButton({required this.onPressed});
  final VoidCallback onPressed;

  @override
  Widget build(BuildContext context) =>
      Button(label: 'Increment', onPressed: onPressed);
}
```

down, and receives user actions through callbacks.

## Notifiers

Notifiers give observable state an owner independent of any one widget. A
notifier can belong to one screen, several widgets, or the whole app; it is not
inherently global. Both `ChangeNotifier` and `ValueNotifier` implement the
lightweight `Listenable` contract, so widgets can rebuild when they publish a
change.

### ChangeNotifier

Use `ChangeNotifier` when related values and actions belong together. This
deployment model owns progress and pause behavior, while `ListenableBuilder`
keeps the UI current:

<CodeDemoSplit
  files={['deployment.dart', 'deployment_view.dart']}
  initialFile="deployment.dart"
  layout="demo-wide"
>
<Fragment slot="code-0">
```dart
class Deployment extends ChangeNotifier {
  int _completed = 1;
  bool _paused = false;

  int get completed => _completed;
  bool get paused => _paused;

  void completeNext() {
    if (_paused || _completed == 3) return;
    _completed++;
    notifyListeners();
  }

  void togglePaused() {
    _paused = !_paused;
    notifyListeners();
  }
}
```
</Fragment>
<Fragment slot="code-1">
```dart
class _DeploymentViewState extends State<DeploymentView> {
  final deployment = Deployment();

  @override
  void dispose() {
    deployment.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => ListenableBuilder(
    listenable: deployment,
    builder: (context, child) => Column(
      children: [
        Text('${deployment.completed} of 3 complete'),
        Text(deployment.paused ? 'Paused' : 'Running'),
        Button(label: 'Complete next', onPressed: deployment.completeNext),
        Button(
          label: deployment.paused ? 'Resume' : 'Pause',
          onPressed: deployment.togglePaused,
        ),
      ],
    ),
  );
}
```
</Fragment>

Create the notifier once and dispose it with its owner. Because the model is
separate from the widget tree, its behavior can be tested without rendering
widgets.

### ValueNotifier

`ValueNotifier<T>` is a `ChangeNotifier` specialized for one typed value. It is
useful when a controller or service exposes one changing value without needing
a larger model:

<CodeDemoSplit
  files={['connection_service.dart', 'connection_panel.dart']}
  initialFile="connection_service.dart"
  layout="demo-wide"
>
<Fragment slot="code-0">
```dart
class ConnectionService {
  final online = ValueNotifier<bool>(false);

  void toggle() => online.value = !online.value;
  void dispose() => online.dispose();
}
```
</Fragment>
<Fragment slot="code-1">
```dart
class _ConnectionPanelState extends State<ConnectionPanel> {
  final connection = ConnectionService();

  @override
  void dispose() {
    connection.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => ValueListenableBuilder<bool>(
    valueListenable: connection.online,
    builder: (context, online, child) => Row(
      children: [
        Text(online ? 'Online' : 'Offline'),
        Button(
          label: online ? 'Disconnect' : 'Connect',
          onPressed: connection.toggle,
        ),
      ],
    ),
  );
}
```
</Fragment>

  slot="demo"
  id="state.value-notifier"

Assigning an equal value does not notify listeners. Prefer immutable values;
mutating a list or map in place does not replace it.

## Sharing state through the tree

A `Scope` makes a value available to one subtree through `BuildContext`, so
the widgets in between do not accept and forward it. A notifier owns and
publishes changing state; a scope controls where a value is available. The
type argument is the key: a descendant reads the nearest `Scope<T>` above it
with `Scope.of<T>(context)`.

```text
CounterScreen (owns counter)
└── Scope<CounterModel>(value: counter)   ← available to this subtree
    ├── Header
    │   └── CounterBadge     ← Scope.of<CounterModel>(context)
    └── Body
        └── CounterPanel     ← Scope.of<CounterModel>(context)
```

`Header` and `Body` do not receive or forward the model. Any descendant can
use its own `BuildContext` to find the nearest `Scope<CounterModel>` above it.

### Sharing a model

The screen still owns the model; the scope shares it. Because `CounterModel`
is a `ChangeNotifier`, every widget that read it rebuilds when it notifies —
no `ListenableBuilder` is needed below the scope:

<CodeDemoSplit
  files={['counter_screen.dart', 'counter_panel.dart']}
  initialFile="counter_screen.dart"
  layout="demo-wide"
>
<Fragment slot="code-0">
```dart
class _CounterScreenState extends State<CounterScreen> {
  final counter = CounterModel();

  @override
  void dispose() {
    counter.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) =>
      Scope(value: counter, child: const CounterPanel());
}
```
</Fragment>
<Fragment slot="code-1">
```dart
class CounterPanel extends StatelessWidget {
  const CounterPanel();

  @override
  Widget build(BuildContext context) {
    final counter = Scope.of<CounterModel>(context);
    return Column(
      children: [
        Text('Count: ${counter.count}'),
        Button(
          label: 'Increment',
          onPressed: counter.increment,
        ),
      ],
    );
  }
}
```
</Fragment>

`Scope.of` works in `build`, in `initState`, and in event handlers. Reading a
scope subscribes the reader. A value that is not a `Listenable` — a settings
object, say — rebuilds its readers when the scope is rebuilt with a value
that is not equal to the previous one.

### Letting the scope own the model

When nothing outside the subtree needs the model, skip the `StatefulWidget`
and let the scope create and dispose it:

<CodeDemoSplit layout="demo-wide">
<Fragment slot="code">
```dart
class CounterScreen extends StatelessWidget {
  const CounterScreen();

  @override
  Widget build(BuildContext context) => Scope<CounterModel>.create(
    create: (context) => CounterModel(),
    child: const CounterPanel(),
  );
}
```
</Fragment>
<FleuryExample
  slot="demo"
  id="state.scope-create"
  cols={38}
  rows={9}
  interactive
/>
</CodeDemoSplit>

`create` runs once, when the scope mounts, and may read scopes above it. On
unmount a `ChangeNotifier` is disposed automatically; pass `dispose:` for
anything else. Rebuilding the widget does not create a new model.

### Scopes and rebuilds

Notification is coarse: every widget that read a scope rebuilds when its
value notifies. That keeps the model simple — there is no field-level
tracking to reason about — and it decides how to split state:

- **One scope per rate of change.** A chat transcript that grows on every
  token and the user's settings belong in two scopes, not one model.
- **Narrow a hot rebuild with `ListenableBuilder`.** Below a scope, wrap only
  the part that depends on a fast-changing notifier.
- **Nearest wins.** An inner `Scope<T>` shadows an outer one. That is also
  how a test overrides a value: wrap the widget under test in its own scope.
- **Keep a value needed in `dispose` in a field.** By then the element has
  left the tree, so `Scope.of` throws.

The built-in `.of` helpers — `Theme.of`, `MediaQuery.of`, `Focus.of`,
`FleuryApp.of` — are scopes read the same way.

## Key APIs

| API | What it does |
|---|---|
| [`StatefulWidget`](#local-state) | Own local UI state |
| [`ChangeNotifier`](#changenotifier) | Publish related observable state |
| [`ValueNotifier<T>`](#valuenotifier) | Publish one observable value |
| [`Scope<T>`](#sharing-state-through-the-tree) | Share a value with a subtree; readers rebuild when it notifies or is replaced |
| [`Scope.create`](#letting-the-scope-own-the-model) | Let the scope create, share, and dispose the value |
