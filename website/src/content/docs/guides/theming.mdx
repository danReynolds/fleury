Themes set the default look of a Fleury app. Define shared colors, text styles,
borders, and interaction feedback in `ThemeData`, then pass it to `FleuryApp`.
Use a widget's `style` property when that widget needs a local override.

| You need to… | Use |
|---|---|
| Theme the whole app | `FleuryApp(theme: …)` |
| Theme one subtree | `Theme(data: …, child: …)` |
| Style widgets | `style: CellStyle(…)` |
| Style widget interactions such as focus, hover, and selection | `CellStyle.interactive(…)` |

## Create a theme

Create a `ThemeData` with the colors and styles your app should share. Fleury
widgets use these values automatically, so changing the theme updates screens,
dialogs, and controls together:

<CodeDemoSplit file="amber_theme.dart">
<Fragment slot="code">
```dart
const amber = ThemeData(
  brightness: Brightness.dark,
  colorScheme: ColorScheme(
    background: RgbColor(0x1C, 0x18, 0x14),
    foreground: RgbColor(0xEB, 0xDB, 0xB2),
    surface: RgbColor(0x2A, 0x24, 0x1E),
    primary: RgbColor(0xE8, 0xA3, 0x3D),
    focus: RgbColor(0xF2, 0xC5, 0x5C),
    success: RgbColor(0x8E, 0xC0, 0x7C),
    warning: RgbColor(0xE8, 0xA3, 0x3D),
    error: RgbColor(0xE5, 0x6B, 0x5B),
    info: RgbColor(0x83, 0xA5, 0x98),
  ),
  mutedStyle: CellStyle(dim: true),
  selectionStyle: CellStyle(inverse: true),
  focusedStyle: CellStyle(bold: true),
  borderStyle: BorderStyle.rounded,
);

FleuryApp(theme: amber, home: const Dashboard());
```
</Fragment>
<FleuryExample slot="demo" id="themes.custom" cols={38} rows={14} surfaceTheme="site" />
</CodeDemoSplit>

`ThemeData.dark()` and `ThemeData.light()` are Fleury's built-in starting
themes. Use `copyWith(...)` when only a few values differ:

```dart
final theme = ThemeData.dark().copyWith(
  colorScheme: ColorScheme.fromSeed(Colors.violet),
  borderStyle: BorderStyle.double,
);
```

Pass the result to `FleuryApp`. If no theme is supplied, Fleury uses its built-in
defaults, so `Theme.of(context)` always returns a value.

## Styling widgets

Every first-party control keeps the common case direct:

<CodeDemoSplit file="local_style.dart">
<Fragment slot="code">
```dart
TextInput(
  controller: query,
  style: const CellStyle(foreground: Colors.cyan),
)
```
</Fragment>
<FleuryExample slot="demo" id="themes.local_style" cols={34} rows={4} interactive />
</CodeDemoSplit>

That style becomes the control's base appearance. It does not erase the
framework's focus, disabled, or validation cues; those still layer on when the
state changes. The same `CellStyle` works on `Text`, `Button`, `Checkbox`,
`Select`, and the rest of the control set.

### CellStyle

A `CellStyle` describes terminal paint: foreground and background colors plus
attributes such as bold, italic, underline, and strikethrough.

<CodeDemoSplit file="cell_style.dart">
<Fragment slot="code">
```dart
Column(children: [
  Text('Default text'),
  Text(
    'Styled text',
    style: CellStyle(
      foreground: RgbColor(0x3D, 0xDC, 0x97),
      bold: true,
      underline: true,
    ),
  ),
]);
```
</Fragment>
<FleuryExample slot="demo" id="themes.cell_style" cols={34} rows={5} />
</CodeDemoSplit>

Styles merge field by field. An unset value inherits; explicitly setting a
boolean attribute to `false` turns that inherited attribute off.

## Interactive styles

Use `CellStyle.interactive` to style interactive widgets when they are focused,
hovered, selected, disabled, or invalid. Assign it to
`ThemeData.interactiveStyle` for app-wide behavior, or pass it to one widget's
ordinary `style` property for a local exception:

<CodeDemoSplit file="interactive_styles.dart" layout="demo-wide">
<Fragment slot="code">
```dart
const theme = ThemeData(
  interactiveStyle: CellStyle.interactive(
    focused: CellStyle(inverse: true, bold: true),
    hovered: CellStyle(underline: true),
    selected: CellStyle(foreground: Colors.green, bold: true),
    invalid: CellStyle(foreground: Colors.red, underline: true),
    disabled: CellStyle(dim: true),
  ),
);

FleuryApp(theme: theme, home: const DeploymentForm());
```
</Fragment>
<FleuryExample
  slot="demo"
  id="themes.interactive_styles"
  cols={52}
  rows={13}
/>
</CodeDemoSplit>

When assigned to `ThemeData.interactiveStyle`, widgets apply the relevant
styles automatically.

### Local interactive styles

The same `style` property accepts either kind of value:

<CodeDemoSplit file="local_interactive_style.dart">
<Fragment slot="code">
```dart
// Only this button changes its focused treatment.
Button(
  label: 'Local focus',
  style: const CellStyle.interactive(
    focused: CellStyle(
      foreground: Colors.cyan,
      underline: true,
    ),
  ),
  onPressed: deploy,
)
```
</Fragment>
<FleuryExample slot="demo" id="themes.local_interactive" cols={46} rows={8} interactive />
</CodeDemoSplit>

A plain `CellStyle` changes the base paint while inherited interaction cues
remain. `CellStyle.interactive` is the local escape hatch when one control's
state should differ.

Use `CellStyle.none` for a state when a widget should deliberately suppress an
inherited cue. It means “apply no paint for this state”; semantics are
unchanged:

<CodeDemoSplit file="neutral_invalid.dart">
<Fragment slot="code">
```dart
FormField(
  validator: () => query.text.isEmpty ? 'Enter a query.' : null,
  child: TextInput(
    controller: query,
    style: const CellStyle.interactive(
      invalid: CellStyle.none,
    ),
  ),
)
```
</Fragment>
<FleuryExample slot="demo" id="themes.invalid_none" cols={48} rows={9} interactive />
</CodeDemoSplit>

When the field reports an error, its validation message still renders and
assistive tooling still receives it; only that input's invalid chrome is
neutral.

## Light and dark themes

Choose the mode when you construct the app theme. `ThemeData.dark()` and
`ThemeData.light()` set `brightness` for you, or pass it explicitly to
`ThemeData(...)`:

```dart
FleuryApp(theme: ThemeData.dark(), home: const Dashboard());
```

Fleury does not guess the terminal's background. When another value needs a
light and dark variant, read the choice through the ambient theme:

```dart
final shadow = context.theme.adaptive(
  light: const AnsiColor(8),
  dark: const AnsiColor(0),
);
```

For code outside a widget build method, use
`theme.brightness.pick(light: ..., dark: ...)`.

## Community themes

[`fleury_themes`](https://github.com/danReynolds/fleury/tree/main/packages/fleury_themes)
is Fleury's community theme collection. It currently includes Nord, Dracula,
Gruvbox Dark, Tokyo Night, Catppuccin Mocha, One Dark, and Solarized in dark
and light variants, and contributions can add more:

```dart
import 'package:fleury_themes/fleury_themes.dart';

FleuryApp(theme: tokyoNight, home: const Dashboard());
```

Arrow through the live picker to compare the same UI across every palette:

<FleuryExample id="themes.gallery" cols={62} rows={18} interactive />

Every preset is a plain `const ThemeData`. The package also exports
`fleuryThemes`, a named list ready for a theme picker.

For a broader comparison—and a custom editor for colors, brightness, and
borders with live widget-state feedback—open the
[Theme studio showcase](/fleury/showcases/themes/).
