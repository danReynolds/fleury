Every Fleury app renders through a theme — a single value, sitting above your
widget tree, that widgets read to decide how their cells look.

The thing worth knowing up front is that widgets ask a theme for *roles* rather
than colours: the error colour, the muted text style, the accent for whatever
is focused. Keeping the colours in one place is what lets you swap a theme and
restyle the whole app at once, and lets the same widget tree look right on a
light terminal, a dark one, or in a browser.

```dart
runApp(const MyApp(), theme: nord);
```

The rest of this guide covers what goes in that second argument: writing a
theme, and the ready-made ones you can use instead.

## Creating a theme

A theme is a plain `const` value you fill in. Here is a complete one, and the
app it produces:

### Apply a theme

For an app-wide theme, pass `theme` to `FleuryApp`. The theme sits above the
app's Navigator, so the home screen, pushed screens, and presented dialogs all
inherit it:

```dart
import 'package:fleury/fleury.dart';

FleuryApp(
  title: 'Status monitor',
  theme: ThemeData(
    brightness: Brightness.dark,
    borderStyle: BorderStyle.rounded,
    colorScheme: const ColorScheme(
      foreground: RgbColor(0xC8, 0xD3, 0xE0),
      primary: RgbColor(0x3D, 0xDC, 0x97),
      warning: RgbColor(0xF5, 0xC2, 0x11),
      error: RgbColor(0xFF, 0x5C, 0x57),
    ),
  ),
  home: const DashboardScreen(),
);
```

`ThemeData.dark()` and `ThemeData.light()` give you sensible defaults to start
from, and `copyWith(...)` overrides individual fields. If `theme` is omitted,
widgets use sensible built-in defaults (`Theme.of(context)` always returns
something).

Use `Theme(data:, child:)` when only one subtree should differ from the app
theme, such as a high-contrast preview or a branded panel. The nearest Theme
wins.

### ColorScheme

The semantic palette — nine roles, named for what they *mean* rather than what
colour they are, so a widget asks for "the error colour" and every theme
answers:

| Role | Used for |
| --- | --- |
| `foreground` / `background` | default text and fill |
| `surface` | raised fills that must be opaque — dialogs, popups |
| `primary` | the main accent: active affordances, progress |
| `focus` | the focused pane or control |
| `success` `warning` `error` `info` | status |

```dart
final scheme = Theme.of(context).colorScheme;
Text('ok',   style: CellStyle(foreground: scheme.success));
Text('uh oh', style: CellStyle(foreground: scheme.error));
```

Colors can be `RgbColor(r, g, b)` for truecolor, `AnsiColor(n)` for a palette
index, or one of the named `Colors.*` constants.

`foreground`, `background` and `surface` are nullable, and leaving one unset is
a real choice: it means "use the terminal's own", which is usually right for
text and background — the user picked their terminal colours. `surface` is the
exception worth setting, because it backs dialogs and must be opaque enough to
hide whatever is painted beneath it.

#### Colour alone is not a cue

`NO_COLOR` (and any 2-colour terminal) drops colour entirely, but keeps
attributes — `dim`, `bold`, `inverse`. So a cue carried only by colour vanishes
for those users, while a cue that *pairs* colour with an attribute survives in
reduced form. That is why the built-in styles below are attribute-first, and
why a status indicator should carry a glyph or weight as well as a hue.

### CellStyle

A cell's appearance: foreground/background plus terminal attributes.

```dart
const CellStyle(
  foreground: RgbColor(0x3D, 0xDC, 0x97),
  bold: true,
  // also: dim, italic, underline, inverse
);
```

`ThemeData` also carries a few ready-made styles widgets use for consistency:
`textStyle` (the default), `mutedStyle` (secondary text), `selectionStyle`
(highlighted rows), and `focusedStyle` (the focused control).

### Multiple styles in one line: RichText

A `Text` carries a single `CellStyle`. To mix styles within one run — a bold word
in a sentence, a colored token in a log line — use `RichText` with a tree of
`TextSpan`s, where each span's style cascades to its children:

```dart
RichText(
  text: TextSpan(
    children: [
      TextSpan(text: 'deploy '),
      TextSpan(text: 'ok', style: CellStyle(foreground: scheme.success, bold: true)),
      TextSpan(text: ' in 1.2s'),
    ],
  ),
)
```

### Painting backgrounds

Backgrounds aren't auto-painted. To fill a region with the theme background, wrap
it in a `Container(color: theme.colorScheme.background, child: …)`.

## Community themes

If you would rather not start from scratch,
[`fleury_themes`](https://github.com/danReynolds/fleury/tree/main/packages/fleury_themes)
ships eight community palettes mapped onto the roles above — Nord, Dracula,
Gruvbox Dark, Tokyo Night, Catppuccin Mocha, One Dark, and Solarized in dark
and light.

```dart
import 'package:fleury_themes/fleury_themes.dart';

runApp(const MyApp(), theme: tokyoNight);
```

Arrow through the list to see each one applied — a real Fleury app running in
your browser, not a screenshot:

`fleuryThemes` is the whole set with display names, ready to drop into a

[package README](https://github.com/danReynolds/fleury/tree/main/packages/fleury_themes)
lists every theme with a link to its upstream project.
