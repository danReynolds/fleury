Use `ListView` for rows and `ScrollView` for a taller block of content.
Both support the keyboard, mouse wheel, and an optional scrollbar.

## Select an item

Use **↑ / ↓** to focus a file, then **Enter** to select it. Clicking a row
selects it too. Moving to another row leaves **Selected** unchanged:

`onSelect` handles both click and Enter. The builder's `highlighted` argument
identifies the row to mark. `ListView` also accepts `children: [...]` when you
already have row widgets; the builder makes it convenient to style each row.

## Scroll a large list

The same builder works for 1,000 tasks, building only visible rows. Here the
**Focused** and **Selected** labels show the two callbacks separately.
`ListController(initialIndex: 24)` starts with task 25 highlighted and visible;
**Selected** stays **None** until you choose a task.

Create the controller once in `State`. Its constructor sets the starting row;
the list and your code both update its live `currentIndex` afterward.

Try **Scroll to 500**, then **Go to 25**. Scrolling leaves the current item
alone; **Go to 25** brings it back into view. Neither selects a task.

`onFocusedItemChanged` reports arrow-key or pointer navigation; `onSelect`
reports the choice. `ListController.currentIndex` remembers the current item
when focus moves to a button. Its marker stays visible, and the demo says
**Focused: outside list**.

Changing `currentIndex` from code updates the list without firing either
interaction callback. A controller listener observes changes from any source.

**Page Up / Page Down** move by a page; **Home / End** move to the first or last
item. The wheel and scrollbar scroll without moving focus or selecting an item.
The scrollbar moves in terminal-cell steps; on a short track over many items,
the wheel and arrow keys give finer control.

`itemKeyBuilder` gives each item a unique, stable identity. Fleury builds the
reverse lookup, keeping the current item and visible rows with their keys when
the data moves. Static lists do not need it.

## See what happens at an edge

Scroll these eight numbered lines. The counter and **TOP / BOTTOM** markers
show exactly where the four-row viewport is.

At **BOTTOM**, press **↓** again: focus moves to **Next**. Turn on
**Contain arrows**, Tab back into the pane, and repeat. Now **↓** stays in the
pane; **Tab** still leaves it.

`EdgeBehavior.bubble` lets an unused arrow move focus onward.
`EdgeBehavior.contain` keeps it in the pane. Lists have the same option.

`ScrollView` lays out its whole child. Give it a bounded height with `SizedBox`
or `Expanded`; keep large collections in `ListView.builder`.
