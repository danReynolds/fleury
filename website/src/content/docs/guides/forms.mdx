A Fleury form is ordinary UI with a reliable submit boundary. Your application
owns the values and layout; `Form` coordinates validation, focuses the first
invalid control, and runs `onSubmit` only when every enabled field is valid.

| You need to… | Use |
|---|---|
| Validate one value | `FormField` around its control |
| Validate and submit a group | `Form` |
| Submit from a button or elsewhere | `FormController` |
| Integrate a custom composite | `FormField.builder` |

There are no field names, schemas, value maps, or required panel layouts.

## Build a form

Own values exactly as you would without a form. Wrap controls that need
validation or external-error handling in `FormField`, then put the resulting
layout inside `Form`. Other controls remain ordinary app-owned widgets:

```dart
final form = FormController();
final name = TextEditingController();
final slug = TextEditingController();
var private = true;

Form(
  controller: form,
  onSubmit: () => createProject(
    name: name.text.trim(),
    slug: slug.text.trim(),
    private: private,
  ),
  child: Column(
    children: [
      FormField(
        validator: () => name.text.trim().isEmpty
            ? 'Enter a project name.'
            : null,
        child: TextInput(
          controller: name,
          semanticLabel: 'Name',
        ),
      ),
      FormField(
        validator: () => RegExp(r'^[a-z0-9-]+$').hasMatch(slug.text)
            ? null
            : 'Use lowercase letters, numbers, and hyphens.',
        child: TextInput(
          controller: slug,
          semanticLabel: 'Slug',
          onSubmit: (_) => form.submit(),
        ),
      ),
      Checkbox(
        value: private,
        label: 'Private project',
        onChanged: (value) => setState(() => private = value),
      ),
      Button(label: 'Create', onPressed: form.submit),
    ],
  ),
)
```

## How fields participate

`FormField(child: …)` finds one first-party value control below it. The control
automatically receives invalid styling and semantics, reports edits, and becomes
the field's focus target. Harmless layout wrappers are fine:

```dart
FormField(
  validator: validateName,
  child: SizedBox(
    width: 32,
    child: TextInput(controller: name),
  ),
)
```

This works with Fleury's text inputs, selection controls, toggles, date and
color pickers, steppers, and range sliders. A `FormField` represents one logical
value, so wrapping multiple value controls is intentionally rejected in debug
builds; use the custom-field escape hatch for a composite value.

The visible error message is rendered below the child by default. Set
`showErrorMessage: false` to place it yourself, or provide `errorBuilder` for a
different presentation. The associated control still exposes the error through
semantics.

## Submission

`submit()` validates every mounted, enabled field before calling `onSubmit`.
It returns `false` when validation rejects the form and `true` after the submit
callback completes. Concurrent calls share the same in-flight submission.

`validate()` waits until pending application-state updates have rebuilt the
fields. This makes it safe to set a controlled error and immediately
`await form.validate()` without manually scheduling work.

Use `isSubmitting` to disable actions and show progress:

```dart
ListenableBuilder(
  listenable: form,
  builder: (context, child) => Button(
    label: form.isSubmitting ? 'Creating…' : 'Create',
    onPressed: form.isSubmitting ? null : form.submit,
  ),
)
```

You can omit the controller when submission stays inside the subtree and call
`Form.of(context).submit()`. Pass a controller when a shortcut, command, app
bar, or parent region needs to validate or submit the form. Create it once,
dispose it with its owning `State`, and attach it to only one mounted form at a
time.

## Advanced patterns

### Server errors

Keep service-returned errors in application state and pass the current one to
`FormField.error`. It is displayed, announced, and blocks submission like a
local validator error. Clear it when the user edits the value:

```dart
FormField(
  error: nameError,
  validator: validateName,
  child: TextInput(
    controller: name,
    onChanged: (_) => setState(() => nameError = null),
  ),
)
```

`form.clearErrors()` hides errors produced by validators without erasing any
values. Controlled server errors remain until your application clears them.

### Custom error styling

Controls use `ThemeData.controlStyle.invalid` when supplied, falling back to
`ThemeData.errorStyle`. Override the `invalid` state on an individual control
when it needs different chrome. Pass `CellStyle.empty` to keep that control
visually neutral while retaining its error message and semantics:

```dart
TextInput(
  controller: query,
  style: const CellStyle.state(invalid: CellStyle.empty),
)
```

See [Theming](/fleury/guides/theming/) for app-wide and per-control state
styling.

### Custom controls

Use `FormField.builder` when one logical value is represented by a custom or
multi-control widget. Supply the focus destination, call `valueChanged()` after
the app-owned value changes, and use `field.error` for custom invalid chrome or
semantics:

```dart
FormField.builder(
  focusNode: startFocus,
  validator: () => end.isBefore(start)
      ? 'End must follow start.'
      : null,
  builder: (context, field) => DateRangeEditor(
    start: start,
    end: end,
    focusNode: startFocus,
    error: field.error,
    onChanged: (range) {
      setState(() {
        start = range.start;
        end = range.end;
      });
      field.valueChanged();
    },
  ),
)
```

### Multi-screen flows

Forms do not impose a wizard abstraction. Keep the values in the parent state,
render one `Form` for the current screen, and advance from that form's
`onSubmit`. Only mounted fields validate, while the app-owned values naturally
survive moving forward and back. Use a nested `Navigator` when the flow needs
its own back stack; otherwise a simple step value is enough.

## API reference

| API | What it does |
|---|---|
| `Form` | Coordinates descendant validation and valid submission |
| `FormField` | Validates one app-owned value and presents its error |
| `FormField.builder` | Integrates a custom or composite value control |
| `FormFieldState` | Exposes `error`, `focusNode`, `validate()`, and `valueChanged()` |
| `FormController` | Validates, submits, clears validator errors, and reports submission state |
