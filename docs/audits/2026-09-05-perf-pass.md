# Core performance pass — 2026-09-05

This continues the [core architecture audit](2026-09-04-core-performance.md)
in [PR #216](https://github.com/danReynolds/fleury/pull/216). Changes were
measured and reviewed individually before the next implementation began.

## 1. Bulk background fill — reviewed

Commit `fe9d45a4`, based on main `8718fd33`. Replaces individual space writes
with a clipped bulk buffer fill, sharing one immutable cell and repairing
wide pairs only at the rectangle edges. The earlier audit records the
17–51% paint-phase reduction across five apps at 120×40.

Review: complete buffer/damage differential checks, wide-pair boundaries,
interactive style resolution, and image placement behavior. Full contributor
gate: 5,305 tests passed, one existing skip; all eight fast performance
gates and the terminal wire gate passed.

## 2. Reuse text measurements — reviewed

`RenderText` now reuses the widths it measured during layout. The common
single-line case uses its existing intrinsic width without another list;
multi-line text retains one integer per laid-out line. Paint also passes
its already-measured grapheme width through an internal buffer bridge, so
placement cannot repeat that measurement. No glyph cache or public API
knob is introduced.

This is a modest gain: roughly 0–5% in the five sample apps beyond bulk
fill. It is retained because it removes duplicate work and keeps layout
and placement on one width decision with little state. The
[receipt](evidence/2026-09-05-text.json) and
[all frame records](evidence/2026-09-05-text-frames.csv) contain the
alternating AOT comparison. Structural layout/repaint counters match.

Review completed before starting change 3:

- Checked empty text, wrapped/unwrapped transitions, same-width text edits,
  constraints, alignment, ellipsis, policy changes, and line-width lifetime.
- Differential placement checks match public grapheme writes for clipped,
  zero-width, narrow, wide, and interaction-style cases, including damage.
- A counting width resolver verifies zero line remeasurement at paint and
  one glyph measurement per glyph. Repeated mutations match fresh layout.
- Internal bridge remains excluded from stable public barrels.
- Core analysis, 600 rendering/selection/policy tests, and all eight fast
  performance gates passed. Embedded client source fingerprint refreshed.

The small sample-app gain does not establish an input-latency improvement.
Background style composition was the next candidate, still prominent after
bulk fill.

## 3. Bulk background composition — reviewed

The shared buffer composition pass now clips once, accesses its cell storage
directly, and reuses the merged style while the source style stays identical.
The cache is two local references, with no map or state retained between
calls. Damage is accumulated once per changed row. Empty/overlay cells and
explicit child backgrounds preserve their original behavior.

Against change 2, paint time fell another 15–28% across all five sample
apps at 120×40. All layout, repaint, cache, and replayed-cell counters match.
See the [receipt](evidence/2026-09-05-background.json) and
[frame measurements](evidence/2026-09-05-background-frames.csv).

Review completed before the next implementation:

- A 500-case differential oracle checks complete cells and damage against
  the previous per-cell composition loop, including clipping, mixed styles,
  explicit backgrounds, wide pairs, and image placements.
- Explicit tests verify a right-edge leading cell still restyles and damages
  its continuation outside the rectangle; continuation-only clips remain
  untouched; damage suppression still applies.
- Reviewed style immutability, cache lifetime, nested backgrounds, and the
  exact damage union. The helper stays out of stable public barrels.
- Core analysis, 3,162 core unit tests (one skip), and all eight fast
  performance gates passed. Embedded client fingerprint refreshed.

## 4. One generated Unicode scalar lookup — reviewed

The remaining profile identified repeated binary searches through Unicode
width properties. The generator now emits one disjoint scalar-class table
with the existing precedence already applied. The resolver searches it once
and applies the surface's width policy to the resulting class. Complex
cluster handling remains in place; this introduces no runtime memoization.

The generator still uses pinned Unicode 17.0.0. Every original property table
is byte-for-byte unchanged. A test independently reconstructs the former
classification from those tables and verifies all 1,114,112 code points and
all four combinations of the two bare-scalar policy axes. Existing variation
selector, flag, keycap, modifier, ZWJ, and lowering tests also pass.

Compared with change 3, paint time improved 16–23% in dashboard, agent,
files, and finance. Editor moved from 34 to 34.5 µs, effectively unchanged.
The [receipt](evidence/2026-09-05-width.json) and
[frame records](evidence/2026-09-05-width-frames.csv) preserve the comparison.

Review completed before the next implementation:

- Checked partition precedence, zero-width scalars, omitted narrow ranges,
  emoji-policy veto, surrogate handling, and all existing curation rules.
- The exhaustive oracle also checks sorted, disjoint, coalesced triples;
  the offline freshness gate binds the output to the generator source.
- Analysis has no new diagnostics. All 3,164 core unit tests, eight fast
  performance gates, and the terminal wire gate passed.
- Browser client grew by 4,968 raw bytes; it remains within the bundle gate
  at 387.4 KiB raw / 101.8 KiB gzip. No Unicode version or output contract
  changed.

## 5. Direct single-code-unit width path — reviewed

A single UTF-16 code unit now uses the generated scalar lookup directly,
avoiding a rune iterator and composite-sequence bookkeeping. Combining marks,
format controls, and lone surrogates still resolve through the generated
zero-width class. Multi-code-unit graphemes retain the complete sequence path.

This adds a further 7–14% paint improvement in dashboard, agent, files, and
finance; editor is unchanged. See the [receipt](evidence/2026-09-05-scalar.json)
and [frame records](evidence/2026-09-05-scalar-frames.csv).

Review completed before the next implementation:

- The exhaustive scalar/policy oracle and existing composite-cluster tests
  cover this branch, including marks, surrogates, and policy overrides.
- Analysis has no new diagnostics. All 605 rendering/selection/policy tests
  and eight fast performance gates passed; the browser client was rebuilt.
- The fast path adds no retained state or separate width-policy exception.

## 6. Reuse equal cell pairs during the exact diff — reviewed

Whole-frame measurement exposed repeated equality work across bulk-filled
runs. The full scan now remembers its last pair of equal immutable cells in
two local references. Identical cells or a repeat of that proven-equal pair
need no value comparison. New pairs still use `Cell.operator ==`; image
placements, changed-cell counts, dirty rows, and bounds retain their existing
logic. Nothing persists between calls or requires invalidation.

The [matched whole-frame receipt](evidence/2026-09-05-diff.json) records the
additional improvement after change 5. The new
`profiling/bin/frame_pipeline_probe.dart` includes buffer preparation, actual
visible text mutations where available, exact diff, commit and post-frame
callbacks. In this per-change receipt it selected only initially mounted
render objects, so finance had no visible localized case and full mode
invalidated that initial subset. The final integrated probe fixes enumeration
by settling adaptive layouts first. Clean timings already covered the complete
paint and diff; clean frames are forced, not idle.

Review completed before the next implementation:

- A 1,000-case differential oracle checks all cells, exact counts, rows and
  bounds, including repeated runs, separate equal allocations, shared copies,
  successive mutations and reverse comparisons. Explicit cases cover false
  versus absent attributes, hyperlinks, and wide-cell roles.
- All 28 diff/frame-loop tests passed, including image-only damage and scroll
  classification. Analysis adds no diagnostics; all eight fast gates and the
  wire gate passed. The browser client was rebuilt.
- A style-pair alternative was also measured. The cell-pair version was
  chosen to keep equality authoritative in one place; it is simpler and
  faster in three of the five apps. No reported-damage shortcut was introduced.

## 7. Share the width decision in buffer text writes — reviewed cleanup

`CellBuffer.writeText` now passes the width it just measured directly to
placement, as `RenderText` already does. This removes a second lookup and
seven lines from the shared writer. A counting resolver verifies one call
per visited cluster, including zero-width marks and left/right clipping;
existing rendering, editing, selection and policy tests cover cell output.

The [receipt](evidence/2026-09-05-write-text.json) and
[frame records](evidence/2026-09-05-write-text-frames.csv) show no measurable
sample-app improvement after the earlier changes. This is a small removal
of duplicate work, not an additional application-level performance claim.
Review is complete: targeted tests and all eight fast gates passed, analysis
adds no diagnostics, and the browser client was rebuilt.

## Stopping boundary and qualification

The large demonstrated wins are in shared frame construction, Unicode
classification and repeated equality work. The retained architecture,
scheduler and exact full-buffer diff remain intact. The final text-writer
cleanup is already below measurable sample-app impact.

Further work on invalidation ownership, reconciliation scratch state, or
replay lifetimes needs a representative active-workload profile that makes
it dominant. The audit did not establish that case. Owner/epoch caches or a
native/isolate rewrite would add lifecycle and consistency obligations to
address costs that these measurements do not identify as the next large win.
The measured style-pair diff alternative was rejected because it duplicates
the cell equality contract. No gate tolerance or benchmark baseline changed.

Individual changes passed their targeted regressions and fast performance
gates before the next change. Final qualification uses:

```
TERM=xterm-256color dart tool/fleury_dev.dart check
TERM=xterm-256color dart tool/fleury_dev.dart benchmark gates
TERM=xterm-256color dart tool/fleury_dev.dart benchmark wire-gate
```

The PR records the final local outcome and commit-specific CI results.
CI also runs the hot-reload probe, documentation build, and generated-project
smoke checks on Linux/macOS/Windows and the minimum supported Dart SDK.
